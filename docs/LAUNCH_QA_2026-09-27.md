# Luma Anesthesia: Final App Check

September 27, 2026

## Verdict

**Not yet cleared for a fully offline release.** The checked online reference flows work, and the confirmed layout and recovery defects have been fixed. This is a software QA report, not a guarantee of zero bugs, a new clinical certification, or App Store approval.

The audit used the [Flutter repository](https://github.com/nmfetzer/Luma-Anesthesia-Flutter) and read-only production data checks. CE loading remained owned by the parallel course session; no production clinical records, purchases, or user accounts were changed during this audit.

## Fixed in this pass

- **Crisis Hub scrolling:** The fixed header and category controls could overflow small iPhones and larger-text layouts. The complete hub now scrolls.
- **Password-reset dialog:** Content now scrolls when a small screen, larger text, and an open keyboard reduce available space.
- **Drug Library connection failures:** Failed loads now show a clear connection message and a working Retry action instead of a perpetual spinner.
- **Medication loading:** The repository retrieves ordered pages of 200 records, with a request timeout, and caches only a complete result. This is memory caching, not persistent offline storage.
- **Drug Library header:** The menu opens a real drawer, the account control navigates to Account using the symbol-and-halo icon, and an inactive header search control was removed. The working in-page search remains.
- **Medication text presentation:** Markdown headings and lists are rendered rather than exposing raw formatting symbols. Stored clinical wording is unchanged.
- **Warning presentation:** Text explicitly beginning “No FDA boxed warning” is displayed under “Warnings & Precautions,” not a heading asserting that a boxed warning exists.
- **Email confirmation routing:** Signup now supplies the same app callback pattern used for account recovery. Live redirect allowlisting and email/device delivery still require an end-to-end test.

## Remaining release gates

### Offline content: not complete

- **Current behavior:** Most clinical repositories fetch from Supabase. Previously loaded medication data can remain in memory during the same session, but restarting the app is not covered by that memory cache.
- **Observed failure:** With the browser app already loaded, disabling the network before opening Drug Library produced the new connection-error screen. Restoring connectivity and pressing Retry restored all 778 medications.
- **Bundled sample:** The medication JSON bundled with the app contains only 47 sample records. It must not be represented as the complete, current offline library.
- **Provider support:** Immediate-help contact text remained available offline. In a fresh web load, the complete treatment-directory asset had not been fetched and did not load after the connection was removed. Its native-bundle behavior still needs device testing.
- **Fonts:** Brand fonts still use runtime Google Fonts loading. Test logs exposed missing bundled-font notices when runtime fetching was disabled; typography is not yet independently offline-ready.
- **Protected content:** Offline downloads must preserve subscription/complimentary-access rules, refresh and expiration behavior, content versions, and sign-out handling. Copying paid prose into a publicly readable asset bundle is not an acceptable shortcut.
- **Always-online actions:** Email signup/recovery, subscription purchases/restoration, external source pages, CE synchronization, and web-hosted charts cannot be promised as offline operations.

### Account creation and recovery: partially verified

- **Live settings:** Email signup is enabled and email confirmation is required. Apple and Google providers were disabled in the live public auth settings at audit time.
- **Not sent:** No real signup confirmation or password-reset email was sent, and no user account was created or altered.
- **Required test:** Create a designated test account, receive and open its confirmation email, sign in, request and complete a reset, then sign in with the new password. Test expired/reused links and the registered app callback on real devices.
- **Configuration check:** Verify the allowed redirect URLs and outbound email configuration in Supabase. A unit-tested redirect string alone does not prove a successful round trip.

### Native iPhone/iPad and purchases: not verified

- **Device availability:** No connected iPhone, iPad, or local device was available for this audit. Chromium viewport tests are not iOS Safari, an iOS simulator, or TestFlight.
- **Required device checks:** Safe areas, keyboard/autofill, rotation, larger accessibility text, external links, warm/cold starts, background/resume, and actual airplane-mode behavior.
- **Required purchase checks:** Store-supplied prices, sandbox purchase, cancellation, restoration, account association, entitlement refresh, and the complimentary CE-access rules.
- **Checkout scope:** The Chrome preview intentionally cannot perform native store purchases. No purchase configuration was enabled or changed in this audit.
- **CE scope:** Finish the course-session upload, then verify course purchase/access, progress, final assessment, and certificates on the same final app revision.

## Recommended next order

1. Implement a versioned, access-aware offline download/cache layer for the launch reference sections and bundle the brand fonts.
2. Complete one real signup/confirmation/password-reset round trip with a designated test email.
3. Install the final integrated build on an iPhone and iPad and test airplane mode, rotation, keyboard, and native purchase/restore.
4. Freeze the release revision after the CE session finishes, then perform a short final regression against that exact build.
